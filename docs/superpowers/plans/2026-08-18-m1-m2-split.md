# 计划 A：m1 / m2 拆成两张独立的图 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `build_graph(select_only)` 一张图两种形状，拆成 `m1 选岗` 与 `m2 勘察表单` 两张各自完整的图，删掉 m2 里的两个幽灵节点，并把 m2 在 UI 上改名为「勘察表单」。

**Architecture:** 纯重构。节点函数一个都不复制（`ensure_ready` 两张图共用同一个函数，各自 `add_node` 一次），拆的是**接线**。`run_layer1` 的输入从「`search_url`/`job_url` 谁非空 + `select_only` 布尔量」两套并存，收敛成 `workflow` 这一个权威输入。

**Tech Stack:** Python 3.11+ / LangGraph / FastAPI / React 18 / pytest / vitest

**Spec:** `docs/superpowers/specs/2026-08-18-m1-m2-m3-split-design.md`

`multisite/layer1_agent.py`，把原来的 `STAGE_ORDER` / `stage_names` 整段替换：

```python
# 两张图各自完整的节点顺序。**刻意不写成「m2 = m1 + 后缀」**——那正是拆图前的形状
# （`STAGE_ORDER[:3]`），它把一个错误的假设编码进了代码：m2 根本不选岗，它拿到的是
# 调用方指定的那一个岗位，`find_jobs` / `write_pending_jobs` 在 m2 里是幽灵节点。
M1_STAGES = ("ensure_ready", "find_jobs", "write_pending_jobs")
M2_STAGES = ("ensure_ready", "open_application",
             "scan_and_classify_fields", "write_pending_application")

_STAGES_BY_WORKFLOW = {"m1": M1_STAGES, "m2": M2_STAGES}


def stage_names(workflow: str) -> tuple[str, ...]:
    """这个 workflow 会经过哪些图节点。前端第 2 层「地铁站」的骨架来源。

    未知 workflow 直接抛——静默返回空元组会让前端画出一张空骨架，
    跟「后端还没开始跑」长得一模一样。
    """
    try:
        return _STAGES_BY_WORKFLOW[workflow]
    except KeyError:
        raise ValueError(f"未知 workflow: {workflow!r}，只有 {sorted(_STAGES_BY_WORKFLOW)}") from None
```

`dashboard/server.py` 的端点：

```python
    return JSONResponse({

        "m2": list(stage_names("m2")),
        "max_steps": MAX_STEPS,
    })
```

`build_graph` 的**节点定义部分原样保留**（那些闭包函数一行不动），只改末尾的组装。把原来的
`stages` 表 + `if not select_only` + 边定义，换成两个 builder 各自组装：

```python
def _compile(stages, workflow, edges, logger, snapshot_provider):
    """把阶段表接成一张图。两个 builder 共用，避免接线逻辑写两遍。"""
    built = tuple(name for name, _, _ in stages)
    if built != stage_names(workflow):
        raise RuntimeError(f"阶段表与 stage_names({workflow!r}) 不一致：{built} vs {stage_names(workflow)}")
    graph = StateGraph(Layer1State)
    for name, fn, summarize in stages:
        graph.add_node(name, traced_stage(name, fn, logger, summarize,
                                          snapshot_provider=snapshot_provider) if logger else fn)
    for a, b in edges:
        graph.add_edge(a, b)
    return graph.compile()
```

`build_select_graph` / `build_survey_graph` 各自给出自己的 `stages` 与 `edges`：

```python
# m1：入口页 → 选岗 → 落库 → 结束。**没有 open_application**，对外零副作用。
edges = [(START, "ensure_ready"), ("ensure_ready", "find_jobs"),
         ("find_jobs", "write_pending_jobs"), ("write_pending_jobs", END)]

# m2：直接从调用方给定的岗位 URL 开表单。**没有 find_jobs / write_pending_jobs**。
edges = [(START, "ensure_ready"), ("ensure_ready", "open_application"),
         ("open_application", "scan_and_classify_fields"),
         ("scan_and_classify_fields", "write_pending_application"),
         ("write_pending_application", END)]
```

两个 builder 内部复用同一个「节点工厂」（现在 `build_graph` 里那一大坨闭包）。
实现方式自选：抽成 `_make_nodes(tools, ...) -> dict[str, callable]`，两个 builder 各取所需。
**约束：节点函数只能有一份定义。**
