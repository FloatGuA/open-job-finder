OpenJobFinder

Boss直聘全流程自动求职 Agent：搜索评分投递、追踪 HR 回应、审批后代发回复，全程人在环。

三条工作流构成闭环：W1 按求职偏好搜索职位、LLM 五维评分、自动投递；W2 同步 HR 会话、分析意图、草拟回复；W3 把人工审批过的回复发出并验证真正落地。 配套简历子系统（视觉模型解析 → 信息池 → 多份定向简历 → 投递时自动匹配发哪份）、跨站点投递探索（m1/m2）与实时可观测 Dashboard。 单人业余项目，从第一行代码到持续真机运行。

W1自动投递

按用户偏好组合多关键词 × 多城市搜索，逐卡抓取 JD 全文，交给 LLM 做五维独立评分（技能匹配、经验、城市、薪资、发展潜力各出一个分数的结构化 JSON），Python 端加权汇总，超过阈值才投递，结果全部落库。 不让 LLM 拍一个整体主观分——分维打分 + 代码加权，结果稳定、可解释、可单独调权重。

幂等与去重：数据库层两道防线（job_id 精确去重 + JD 内容指纹去重），程序崩溃重启后安全续跑，不会重复打扰同一职位。
源码 pipeline/w1 tools/llm

W2会话同步与意图分析

拦截 Boss 站内 API 拿到会话全量元数据（真实时间戳、加密 job_id），实现投递记录与 HR 会话的硬关联；脏检查只同步有新消息的会话，把全量扫描降为增量。逐会话读取完整消息历史后，LLM 分析 HR 意图（约面、索简历、婉拒…），需要回应的草拟一条建议回复——只草拟，不发送。

读/析解耦：读取成功与分析成功分别记录时间戳。此前 LLM 偶发超时会让一批会话被判「无变化」而永久跳过——解耦后失败的分析下轮自动重试，这类隐形丢失清零。另有平台诱导消息（伪装成 HR 发言的运营提示）识别重分类，防止污染意图判断。
源码 pipeline/w2

W3人工审批后发送

W2 草拟的回复进入 Dashboard 审批队列，用户批准 / 修改 / 驳回后 W3 才动手。发送前有新鲜度闸：如果会话已有新动态（比如上一条已是我方消息），草稿自动作废退回重新分析，绝不盲发过时内容。

「动作做了 ≠ 结果发生了」：点了发送不算数——W3 发送后重新扫描会话，确认消息真实出现在对话里才标记已发。对真人不可逆的操作，验证的必须是结果而不是动作。
源码 pipeline/w3

简历简历子系统

上传 PDF 由视觉模型解析——读页面渲染图而非抽取文本，排版型简历不丢结构——进入信息池：关于用户的全部素材主库，只增改不删，写盘前自动快照、可回滚。从池中拖拽组合出多份面向不同岗位的简历，A4 分页预览与导出 PDF 同源渲染。投递时由确定性关键词匹配决定「投这个岗发哪份」——匹配路由刻意不用 LLM，要的是可解释、可预期。

产品边界：简历内容由用户掌控，Agent 只选不写。自动发送默认关闭，每份简历须显式勾选「允许发送」；全部匹配不上时用指定兜底，没有兜底就拒发——宁可不发，不乱发。

跨站点投递（m1/m2）

面向 Boss 之外的企业官网招聘系统：agent 自主勘察站点结构并选岗（m1），打开申请表并分类字段（m2）。每阶段停在人工审批点，提交类点击由代码硬拦——不存在任何自动提交表单的路径。

工程约定与教训

三条约定，都不是从书上抄的——每条背后有一次真实事故或一个真实约束。

一个状态转换，只有一份 SQL

一次审查连抓四例同构漂移：同一个状态转换在代码里存在多份实现，各写各的 CASE 分支。最危险的一例是 mark_reply_sent 有三份，其中一份把状态写成 NULL 而不是终态——意味着已发送的回复可能被当成未处理重发，给同一位 HR 二次打扰。此后立铁律：tracker 独占全部状态机 SQL，工具层只做薄壳契约，端点里一行 SQL 都不许出现。发现分叉不做两边同步，选对的那版收敛掉另一版。

可观测：没失败 ≠ 验证到了

每次运行的全部步骤事件落 JSONL 文件（SSE 实时推送只是它的投影），Dashboard 可逐事件回放任意历史 run；配套诊断器把「覆盖」拆成三态——通过、失败、根本没走到。一条路径没报错，可能只是因为它压根没执行；把这件事显式化之后，扫描 553 个历史 run 找出过一批静默未覆盖的分支。

LLM 的使用边界：models judge, code decides

LLM 只做真正需要判断的事：职位评分、意图分析、回复草拟。路由、重试、状态码处理、简历匹配全是确定性代码——凡是状态已经决定结果的地方，绝不引入模型的不确定性。LLM 调用封装在多 Provider 降级链里（Anthropic API / Ollama 本地 / OpenAI 兼容 / CLI），按 fast / balanced / powerful 能力分级路由，单一 provider 挂掉不影响流程。守门的是 1573 项自动化测试（pytest + 前端 vitest），改动不绿不收工。

诚实的技术边界

这不是分布式系统，也不试图伪装成一个。单进程单线程同步——DrissionPage 不支持 async，而且单个求职账号的浏览器操作本质上就是串行的；SQLite——单用户、低频写入，一个文件就是全部状态，备份等于复制；不做多租户——它服务一个人找工作，不服务一个平台。

选型跟着真实约束走，而不是跟着简历关键词走。复杂度花在了刀刃上：反爬对抗、状态机正确性、人在环安全、可观测回放。
