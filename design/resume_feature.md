# 简历功能设计（拆成三个功能）

> 状态：需求记录 + 待逐项确认细节。确认后再实现。
> 记录时间：2026-06-29

## 背景与现状

- **已有**：上传简历(PDF/DOCX) → `parse_resume_file` → `data/resume_base.yaml`（已接通，设置页可上传）。
- **已有积木**：`ResumeManager`（`load_base` / `apply_patch` / `render_pdf` / `generate_for_job`），`ScoreResult.resume_patch` 字段（评分 LLM 设计上产出 {summary, highlights}）。但 `generate_for_job` **全项目无人调用**，定制简历未落地。
- **PDF 渲染**：原设计用 WeasyPrint，但本机 Windows 缺 GTK 系统库（libgobject）装不上；**已验证改用 Chromium CDP `Page.printToPDF` 可行**（复用项目已有 DrissionPage 浏览器，零新增系统依赖）。
- **现有发送机制**：W1 投递 = 点 Boss「投递」按钮（发 Boss 预设的打招呼语 + 简历）；W2 发简历 = 点 Boss 工具栏「发送简历」按钮（发 Boss 账号里的简历）。**除 W3（发已批准回复）外，没有"发送自定义内容"的流程。** 发自定义 PDF 简历的能力当前完全没有。

---

## 功能一：简历解析 + 段落化（积木库）

**目标**：把简历 + 用户自我描述，拆成"可排列组合的段落/块"。基本信息以外的块，额外生成一个简单概括。

- 输入：`resume_base.yaml` + 用户自我描述文本。
- 输出：结构化"块库"，按类别分组（如 基本信息 / 实习经历 / 个人特长 / ...）；非基本信息的块各带一个"简单概括"。
- 用途：作为功能二排列组合的素材。

**已确认（Q1，2026-06-29）**：
- Q1.1 ✅ 固定一套常见类别：基本信息 / 教育 / 实习经历 / 项目经历 / 技能特长 / 获奖荣誉。
- Q1.2 ✅ 简历 navigator 内置输入/编辑区，用户可自行录入；交互参考 FlowCV 等在线简历站（分区块、每区块条目可增删改）。上传解析用于**预填**这些区块。
- Q1.3 ✅ 一段经历 = 一个块（整段含多条 bullet）。
- Q1.4（我的建议，待默认）：每个非基本信息块自动生成的"简单概括" = 给功能二 LLM 挑块用 + 同时小字展示给用户（可一眼看出每块讲什么）。
- Q1.5 ✅ 存 `data/resume_blocks.yaml`（编辑的单一真相）；简历页可改/增/删/排序。上传 `resume_base.yaml` 仅作解析来源预填进 blocks。

**我的意见（功能一）**：
- 「基本信息」做成固定字段（姓名/电话/邮箱/城市/学历/期望岗位…），其余类别做成"块列表"（每块=一段经历，含标题/时间/多条 bullet）。这与 FlowCV 一致，也好渲染。
- `resume_blocks.yaml` 作为唯一可编辑源；上传简历=一次性预填，之后以 blocks 为准（避免两份数据打架）。
- "简单概括"由 LLM 生成（balanced 链），存进每个块，编辑块时可重算。

## 功能二：岗位特化生成

**目标**：按 JD 排列组合块库 → 生成 ①岗位特化简历 ②打招呼语。强调"排列组合用户提供的信息，不杜撰"。

- 输入：块库（功能一）+ 某岗位 JD。
- 输出：岗位特化简历（选/排/组合相关块）+ 该岗位的打招呼语。

**已确认（Q2，2026-06-29）**：
- Q2.1 ✅ 按需生成：简历页手动选岗位生成预览 + 实际发送时自动生成。不在 W1 给所有岗位预生成。
- Q2.2 ✅ 存「组合方案」（结构化：选哪些块/顺序/定制 summary/招呼语），预览或发送时用 Chromium CDP 渲染 PDF。不囤 PDF、可重渲染。
- Q2.3 ✅ 简历与招呼语**分开按需生成**。
- Q2.4（建议）：用 generation 链（无则 fallback scoring），与现有 LLM 路由一致。
- **新增：预制模板**：允许用户为某类岗位预制简历模板（例：游戏策划类岗位一套模板）。生成时该类岗位直接用预制模板（块组合），而非每次都让 LLM 从零排列组合。

**预制模板（已确认）**：
- Q2.5 ✅ 关键词/规则自动匹配：模板设关键词（如「策划」「游戏」），岗位标题/JD 命中则用该模板；命中多个取最优、都不中则 LLM 自动组合。
- Q2.6 ✅ 预制为起点，LLM 再按 JD 微调 summary 与招呼语（更贴合）。
- 模板内容：一个命名模板 = {匹配关键词, 选定块组合(顺序), 可选招呼语风格}。存 `data/resume_templates.yaml`，简历页可管理。

## 整合实现计划（全部细节已确认 2026-06-29）

**功能一 · 简历积木库**
- 数据：`data/resume_blocks.yaml` = {基本信息(固定字段), 教育[], 实习经历[], 项目经历[], 技能特长[], 获奖荣誉[]}；每个非基本信息块={标题,时间,bullets[],summary(LLM生成)}。
- 后端：解析上传简历(+自我描述)→预填 blocks；LLM 为每块生成 summary；CRUD blocks。
- 前端：「简历」navigator（新），FlowCV 式分区编辑器（增删改排序）+ 自我描述输入框。

**功能二 · 岗位特化生成**
- 按需生成（手动预览 + 发送时）；存「组合方案」结构化，按需 Chromium-CDP 渲染 PDF。
- 简历与招呼语分开按需生成；generation 链。
- 预制模板 `data/resume_templates.yaml`={名称,匹配关键词,块组合,招呼语风格}；岗位关键词命中→用模板为起点→LLM 按 JD 微调；不中→LLM 自动组合。

**功能三 · 发送**
- 招呼语：W1 投递后生成→入审批队列→W3 发（复用审批+W3）。
- 简历：先调研 Boss 附件上传，再实现。

**实现顺序**：功能一 → 功能二（含预制模板）→ 功能三（招呼语经 W3 / 简历发送调研后做）。
**PDF 渲染**：统一用 Chromium CDP `Page.printToPDF`（弃 WeasyPrint）。
