## 判断岗位时注意

- 按岗位**实际做什么**判断和归类，不要只看标题里有没有关键词。比如"市场营销 - 产品营销方向"是市场营销岗不是产品岗；"产品服务代表"是客服不是产品岗；"物流运营"跟运营方向不是一回事。
- **AI NATIVE 优先于开发/产品。** 只要岗位**职责里**出现 **LLM / 大模型 / Agent / 多模态 / AIGC / 生成式** 这类字眼，就归 **AI NATIVE**，哪怕标题写的是"算法工程师""开发工程师""产品经理"。这一类很容易被埋进"开发"里——它们标题长得就像普通研发岗，只有看职责正文才能发现。
- **AI 方向的产品经理归 AI NATIVE，不归产品。** 比如"产品经理 - 软件AI方向"这种，职责是做 AI 功能的产品设计，归 **AI NATIVE**。"产品"那一类留给不带 AI 的常规产品岗。
- **归类要诚实。** 名额是按类别分的，把一个岗位硬塞进一个还有空位的类别，只会让我最后拿到一份错的清单。拿不准归哪类就选最接近的那个，并在 `why` 里说明你的犹豫。
- 一个岗位如果完全不属于名额表里的任何类别，就照你的判断给一个最接近的类别名，并在 `why` 里说明——**不要因为拿不准就干脆不回这条**，缺的条目会被当成未分类处理。

## 输出格式

只输出一个 JSON 数组，每条对应一个岗位，`index` 必须对应上面"待分类的岗位"里的编号（从 0 开始），不要跳过、不要重排：

```json
[{"index": 0, "category": "类别名", "why": "一句话说明依据", "title": "岗位标题", "company": "公司名"}]
```

`category` 必须是"本次名额"里出现过的类别名，一字不差。

**`title` 是这条岗位干净的标题**（比如"AI应用开发工程师"）——从给你的内容里把标题这几个字择出来，不要把地点、标签、部门缩写这些一起带上，也不要整段原样照抄。

**`company` 是招聘这个岗位的公司名**；读不出来（这个站的卡片可能压根没写公司名）就给空串 `""`，这是正常情况，不要瞎编一个。

每条都必须带上 `title` 和 `company` 这两个字段，即使值是空串。除了这个 JSON 数组，不要输出任何别的文字。
