## 你要搞清楚的几件事

### 1. 顶层怎么分类（分几个"桶"）

`take_snapshot` 看入口页，找出岗位列表上方的筛选器/分类标签——很多招聘站会把岗位分成几个大类（比如"应届生/实习生""研发类/非研发类""技术/产品/设计"）。把每一个筛选维度都记下来：这个维度叫什么、下面有哪些选项。

一个站可能有不止一个筛选维度（比如"应聘项目"和"工作地点"是两个不同的维度），都要记。

### 2. 每个维度能不能同时选好几个（多选 vs 互斥）

**这件事光看页面看不出来**——checkbox 外观也可能其实是互斥的，页面上也不会显示"当前选中了哪个"。

**必须每个维度各测一次，不能测一个就推广到其他维度。** 同一个站的不同维度经常不一样，而这个字段是**按维度**记录的。（真实教训：某站的「应聘项目」是多选、「工作城市」也是多选，但因为只测了前者、后者被记成互斥，之后每一轮扫桶都按错的方式操作。）

判断方法——**回读 `checked` 状态，不要看岗位总数**：

1. 用 `set_filter_option` 勾选这个维度下的选项 A（工具会回读确认，返回"已勾上"就是真的设上了）
2. 再用 `set_filter_option` 勾选**同一维度**下的选项 B
3. `take_snapshot`，看**选项 A 现在还是不是 `checked`**
   - A 仍然 `checked`（A、B 同时勾着）→ **多选**，填 `true`
   - A 变回没勾（勾 B 把 A 顶掉了）→ **互斥**，填 `false`
4. 测完把这个维度的选项都取消，再去测下一个维度——**别把上一个维度的筛选条件留着**，它会影响你后面读到的一切

**为什么不能看岗位总数**：那个数字是**滞后的**——实测勾上第二个城市之后总数纹丝不动，而 `checked` 立刻就有了。拿滞后的量做判据会得出相反的结论。

选项藏在折叠分组里时 `set_filter_option` 会告诉你"先展开分组"，照做即可（**分组可能嵌好几层**，一层层展开到看见那个选项为止）。

这个试探每个维度最多用 {{max_filter_clicks}} 次点击。实在测不出来的维度填 `false`——更保守，后续只会当它是互斥来操作；同时在 `important_notes` 里写明哪个维度没测出来。

### 3. 怎么读到"共 N 个岗位"这行文字

把它写成一个**正则表达式**，必须带一个数字捕获组。比如岗位列表页写着"共940个岗位"，正则就是 `共(\d+)个岗位`。如果这个站根本没有这类计数文字，这一项留空。

### 4. 一个岗位的 URL 怎么拿到

点开列表里第一个岗位（或看它在快照里长什么样），判断属于哪一种：

- **`link_in_row`**：这张卡片本身在快照里就是一个 `link` 节点、带 `url="..."` 属性——最简单的情况
- **`new_tab_on_click`**：点击后没有明显反应，但用 `list_pages` 一看多了一个新标签页——详情页开在新标签页里。确认后记得 `close_page` 把它关掉
- **`id_template`**：卡片没有现成链接，但你能看出岗位有个数字 ID，且 URL 有固定格式（比如 `https://x.com/job/12345`）——这种情况把 URL 模板记下来，用 `{id}` 占位符标出数字的位置（例：`https://x.com/job/{id}`）

### 5. 列表怎么切成一行一行

先看快照里每个岗位卡片是什么形状，分两种情况：

- **每个岗位本身就是一个独立节点**（通常是一个 `link`，标题、地点、类型等信息全部拼在它的 accessible name 里，这个节点自己还带 `url="..."` 属性）——这种站直接把节点本身当作一行，不需要再找锚点文字。填 `row_split=container_per_row`，**`row_anchor` 这时候填的不是文字，而是这些岗位链接的 url 里都会出现、导航栏等其他链接不会出现的那一段子串**（比如 `/position/`）——代码会用它来把岗位链接从页面上其它的 `link` 节点（导航栏、页脚）里挑出来。
  例：某招聘站快照里每个岗位是一个 `link`，name 里拼着"AI Agent算法工程师（...） 上海、杭州、深圳 正式 研发 - 算法 ...detail"，url 是 `https://xxx.feishu.cn/campus/position/7675998559749048626/detail`；同一页的导航链接（"职位"/"产品官网"/"社会招聘"等）url 都不带 `/position/`。这种站填 `row_split=container_per_row`，`row_anchor=/position/`。

- **岗位信息平铺成一串 `StaticText`，没有容器包裹**（一个岗位的标题、地点、标签分别是好几个独立的 `StaticText` 节点，前后紧挨着下一个岗位的 `StaticText`，肉眼看不出哪几行属于同一个岗位）——这种站找一段**每个岗位行里必现且仅出现一次**的文字作为锚点（比如"工作地点："这种每行都有、且只出现一次的字段标签），把它记进 `row_anchor`，`row_split` 填 `anchor_text`。
  例：某招聘站快照里岗位标题（"AI全栈工程师"）、类别（"技术"）、"工作地点："、城市列表挨个平铺，一个岗位挨着下一个岗位，没有任何容器把它们框在一起；但"工作地点："这个 `StaticText` 每个岗位恰好出现一次。这种站填 `row_split=anchor_text`，`row_anchor=工作地点：`。

**`row_anchor` 在两种模式下含义完全不同**——`anchor_text` 模式下它是"节点 name 要精确匹配的一段文字"，`container_per_row` 模式下它是"url 里要包含的一段子串"，不要把两种模式的填法搞混。

如果两种形状都不像，或者这个站的列表结构你判断不出规律，**不要硬填**——可以只报你已经确定的其他字段，在 `important_notes` 里说明卡在哪，不要为了凑齐 `row_split` 而编一个不存在的锚点。

### 6. 怎么翻页

`next_button`（有"下一页"按钮）/ `url_param`（翻页靠改 URL 参数）/ `infinite_scroll`（往下滚自动加载）/ `none`（一页就装完了，没有分页）。

### 7. 重新导航一次筛选器还会不会保留（顺带留意，不用专门测）

如果你在这次探索中恰好发现"换了个 URL 或刷新页面之后筛选器还留着"（不用专门去验证），就把 `filters_survive_reload` 填 `true`；没注意到就填 `false`——这是更保守的默认值。

## 记录

**你的产出是一次次的 `record_site_manual` 调用，不是最后的一段总结。** 不用等把以上 8 件事全部搞清楚才第一次调用——**每确认一件事就调一次**，把你这次弄清楚的那部分字段报上去；没弄清楚的字段不用管、留给下一次调用（或留给下一次探索之后再报）。

`record_site_manual` 每次都会告诉你**已经确认了什么、必填的几项里还差什么**——以它返回的进度为准，不要自己在脑子里记账。它说"手册已完整、可以结束了"，就停止操作，不要再探、也不要再总结一段话；它说还差什么，就接着去把那部分搞清楚，再调用一次。

如果发现某几件事实在搞不清楚（比如列表结构既没有容器也找不到唯一锚点），**不要硬填一个最接近的答案**——那会让后面抓岗位的代码去点一个根本不存在的东西，抓回一堆垃圾还看不出错在哪。老老实实调用 `record_site_manual` 报上你确定的部分、在 `important_notes` 里说明卡在哪一步、原因是什么，然后停止操作。

**结束前必须再调用一次 `record_site_manual`，把你当下已经确定的字段报上去——哪怕还有没搞清楚的**。这个工具支持增量调用，报了不会丢、不会覆盖掉之前确认的部分。你自己反复琢磨某个字段该填什么、犹豫不决时，不要一直在文字里打转——先把已经确定的部分报出去，卡住不报等于这次探索白探了。

## 技术注意

- 每次点击/导航之后页面都会变，**旧快照里的 uid 全部作废**，必须重新 `take_snapshot` 再用新的 uid。
- **点了却什么都没变？先查是不是开了新标签页。** 用 `list_pages` 看有几页，`select_page` 切过去看，看完 `close_page` 关掉再切回列表。
- **筛选选项点不动（报 "did not become interactive"）？那个分组多半是收起的。** 先点该分组的标题按钮展开，再点里面的选项。别对同一个选项反复点——同一个调用连续失败两次之后会被直接拦下，重试不会有不同结果。
